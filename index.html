THE DETAILS

Before you begin.

Which account pays for the model?+

The subagent uses its harness’s existing account, API key, or provider. Subscription allowances and API charges follow that setup. Bridge does not provide model access or sell another subscription.

What stays on my computer?+

Bridge’s rules and coordination run locally. Your agents still send prompts and code to their configured model providers. A shared project folder does not copy the whole chat: the orchestrator supplies the context each task needs.

How do results and follow-ups work?+

Your main agent (the orchestrator) sends a task and the context it needs. The subagent works in the same project folder using its own harness, tools, and account. Independent work can continue in the background. First-time setup may need a reload or hook approval. Supported integrations return results to the session that started the task. Codex hooks deliver during active turns or when a turn stops; an idle chat receives pending results next turn. Follow-ups reuse the same worker conversation while its process is alive. Restarting the harness ends that continuity.

What do “can use” and “should use” mean?+

“Can use” lets the orchestrator decide whether to delegate. “Should use” instructs it to delegate matching tasks; it cannot guarantee a model will obey. Multiple agents or models are alternatives: the orchestrator picks one of each per task. Bridge enforces those allowed choices when a task runs.
